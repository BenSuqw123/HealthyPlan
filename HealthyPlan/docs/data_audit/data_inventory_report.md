## Scope and classification rules

The repository contains only `data/`; it has no application code, preprocessing scripts, README, schema, source manifest, validation program, or Git history. Therefore, “consumer” and “currently used” cannot be verified from repository references. A file described as a “probable current candidate” is inferred only from its name, later modification time, larger schema, and superset of IDs; it is not proven authoritative.

Counts use these mutually exclusive audit categories:

- 58 original raw source files: 25 Compendium HTML snapshots, 13 USDA CSV files, 19 RAG HTML snapshots, and 1 Vietnamese Food Composition Table PDF.
- 22 intermediate files: 19 extracted RAG text files plus 3 base/unreviewed RAG CSVs.
- 8 final/candidate datasets: four core CSVs, the RAG source registry, and three reviewed RAG CSVs.
- Total: 88 data files. Every file opened successfully. All CSVs parsed as UTF-8/UTF-8 BOM.

“Complete traceability” means preserved raw evidence, adequate source metadata, and a reproducible transformation. Under that strict definition, 0 of 8 final datasets is complete because no transformation scripts exist. `exercise_activities.csv` nevertheless has exact row-level raw evidence, and the USDA part of `single_food_items.csv` has strong row-level evidence.

- No file is proven unused because the repository contains no code to search beyond the data files themselves.

- `food_category.csv` is byte-for-byte duplicated across USDA release folders, and most `measure_unit.csv` content overlaps, but both copies belong to separate official release snapshots. They are not removal candidates.
- No file is classified “safe to delete.” The most permissive classification is **safe to archive after owner confirmation** for the three base RAG CSVs, and only after the authoritative version and generation history are documented.
